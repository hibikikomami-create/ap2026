# MySheet — クリエイターのための収益管理ツール

個人事業主・小規模ブランドが、対話型ステップ入力で事業情報を整理し、商品ごとの収益シミュレーション・管理シート・発注書をかんたんに作れるWebアプリです。

---

## セットアップ・起動方法

```bash
# 1. 依存関係インストール
npm install

# 2. 開発サーバー起動（0.0.0.0でバインドするためどの環境でも到達可能）
npm run dev
```

起動後、ターミナルに以下のようなログが出ます：

```
  VITE v8.0.9  ready in 355 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: http://<あなたのIP>:5173/
```

## 確認URL（実測済み・HTTP 200確認）

| 環境 | URL |
|---|---|
| ローカル（ループバック） | http://localhost:5173 |
| ローカル（明示的IP） | http://127.0.0.1:5173 |
| ネットワーク経由（LAN・コンテナ） | http://0.0.0.0:5173 または上記ログのNetwork URL |

> **重要**: `npm run dev` は **セッション中のみ** サーバーを保持します。
> ターミナルを閉じた・セッションが切れた場合は再度 `npm run dev` を実行してください。

## 既知の不具合への対処

### ① URL確認できなかった原因（解決済み）

**原因**: `npm run dev` はターミナルセッション中のみ動作します。セッションが終了するとプロセスも停止するため、次のセッションではサーバーが存在しません。

**対処**: 
- `vite.config.ts` に `server.host: '0.0.0.0'` を明示的に設定
- `npm run dev` は毎回実行が必要なことをREADMEに明記
- 環境によっては `Network: http://xxx.xxx.xxx.xxx:5173/` のURLを使用

### ② PDF日本語文字化け（解決済み）

**原因**: jsPDFのデフォルトフォント（helvetica）はCJK文字非対応。日本語テキストをpdf.text()に渡すと文字化けが発生します。

**採用した対策: ブラウザネイティブ印刷方式**

```
以前: jsPDF → pdf.text(日本語) → 文字化け
現在: HTML生成 → 新ウィンドウで開く → window.print() → ブラウザが正しくレンダリング
```

- Noto Sans JP（Google Fonts）をインポートしたHTMLを生成
- `document.fonts.ready` でフォント読み込み完了後に自動的に印刷ダイアログを起動
- ユーザーが「PDFとして保存」を選択することで完全な日本語PDFを取得可能
- ポップアップブロッカーで弾かれた場合はHTMLファイルとしてダウンロードにフォールバック
- jsPDF除去により **バンドルサイズが976KB→611KB（-37%）** に削減

**本実装での追加改善案**:
- `@react-pdf/renderer` + Noto Sans JPフォントファイルで完全自動PDF化
- またはPuppeteer/Playwrightをサーバーサイドで使用

### ③ localStorage 5MB制限（対処済み）

**現状の保存対象** (`src/lib/storage.ts` + Zustandのpartialize):

| データ | 保存対象 | 最大件数 |
|---|---|---|
| products | ✅ 永続化 | 500件でトリミング |
| projects | ✅ 永続化 | 無制限（数件想定） |
| documents | ✅ 永続化 | 100件でトリミング |
| settings | ✅ 永続化 | 軽量（1件） |
| currentProject | ✅ 永続化 | 1件 |
| selectedProductIds | ❌ 非永続化 | — |
| onboarding | ❌ 非永続化 | — |
| onboardingStep | ❌ 非永続化 | — |

**入れた軽減策**:
- `createJSONStorage` にカスタムアダプタを実装
- `QuotaExceededError` を try-catch で検知し `console.warn` に留める（クラッシュしない）
- 3MB超過時に警告ログを出力
- 件数が増えた場合は古いデータから自動トリミング（FIFO）

**本実装時の推奨保存方式**:
- Supabase / PlanetScale などのサーバーDB（メインストア）
- SWR / React Query でクライアント側キャッシュ
- オフライン対応が必要なら IndexedDB（Dexie.js）
